# 트랙 B 앞 k개 패킷 시간 분할 평가 (k=5·10)

[추출기](track_b_extractor.md)가 만든 HIKARI 플로우로, 플로우의 **앞 k개 페이로드 패킷만** 입력해 정상/공격을 분류한다. 04-12 학습 → 04-17 시험과 그 역방향(날짜가 곧 분할). 결과는 **초기 페이로드 패킷 수에 따른 오프라인 분류 성능**이며 실시간 지연·운영 오탐의 근거가 아니다. 코드는 `src/track_b/early_eval.py`.

## 조건

| 항목 | 내용 |
|---|---|
| 데이터 | Bruteforce-XML 캡처 두 개. 공격 5,141(1,216 + 3,925), 정상 6,442(1,950 + 4,492) |
| k | 5, 10. 공격 플로우가 모두 12개 이하라 k=20·30은 평가하지 않는다 |
| 입력 | `seq`: 앞 k개 값만 남기고 30칸 뒤쪽 0 패딩. `counts`: 앞 k개로 계산한 패킷 수·길이 합 4개(기준선) |
| 모델 | RF·LightGBM, `src/common/models.py`의 고정 설정(100 trees, balanced). 시드 0·1·2는 모델 시드만 바꾼다(분할은 날짜라 고정) |
| 총 실행 | 2방향 × k 2 × 입력 2 × 모델 2 × 시드 3 = 48회 |
| 지표 | 고정 2클래스 macro-F1·정확도. 전체/`reached_k`/`short` 부분집합 점수는 `subsets.csv` |

## 결과 (48회 모두 macro-F1 ≥ 0.9977)

| 방향 | 입력 | k=5 RF / LightGBM | k=10 RF / LightGBM |
|---|---|---|---|
| 04-12→04-17 | seq | 1.0000 / 0.9998 | 1.0000 / 0.9998 |
| 04-12→04-17 | counts | 0.9996 / 0.9989 | 0.9986 / 0.9977 |
| 04-17→04-12 | seq | 1.0000 / 0.9997 | 1.0000 / 1.0000 |
| 04-17→04-12 | counts | 0.9993 / 1.0000 | 1.0000 / 0.9997 |

평균 macro-F1(시드 3개). 시드 표준편차는 0~0.0002이며 같은 시험 집합에 모델 시드만 바꾼 값이라 독립 신뢰구간이 아니다. 행별 예측은 `DATA_DIR/predictions/track_b_early_<run-id>/`에만 있다.

`subsets.csv`: k에 도달한 행(`reached_k`)만 따로 봐도 정확도 1.0이고, 짧은 흐름(`short`)은 **모두 정상**이라 공격 recall은 NA다(공격 플로우는 k=5·10에 모두 도달한다).

판정 시점의 하한(`latency.csv`, k번째 페이로드 패킷의 첫 패킷 대비 도달 초, 중앙값): 공격 k=5 약 0.075초, k=10 약 0.16초. 정상은 k=5 약 0.18~0.21초, k=10 약 0.48~0.55초(p90 2.9~5.5초). 이는 **패킷을 받은 시각의 하한**이고 모델 추론 시간·운영 지연은 포함하지 않는다.

## 해석: 이 점수는 조기 탐지 능력의 근거가 아니다

1. **분리가 너무 쉽다.** 앞 5개 패킷 패턴이 공격은 5,141개 중 **6종**, 정상은 6,442개 중 2,775종이고, 공격과 정상이 공유하는 패턴은 **0개**다. 10개로 늘려도 공격 59종, 공유 0개다. 공격 대다수가 `517,-2896,-801,80,176`(4,049개) 같은 한 패턴이다
2. **첫 값 하나로도 거의 구분된다.** 첫 페이로드 패킷의 길이 하나(`seq_0`)만 쓰는 깊이 2 결정 트리가 시간 분할에서 정확도 0.9975~0.9986이다. 길이 합 같은 요약(`counts`)도 0.9977 이상이다. 반면 "몇 개를 받았는가"(`n_seen`)만으로는 0.53~0.61로 우연 수준이다. 즉 패킷 수가 아니라 **첫 패킷의 크기 지문**으로 갈린다
3. plan.md의 "HIKARI 공격은 단일 도구 산출물이라 JA3가 사실상 공격자 식별자"와 같은 현상이다. 모델이 공격 행위를 일반화했다기보다, 한 도구의 초반 패킷 모양을 외운 것과 구분되지 않는다
4. 따라서 이 결과로 "조기 탐지가 된다"거나 "모델이 초반 패킷 순서를 이해한다"고 주장하지 않는다. 쓸 수 있는 문장은 "HIKARI Bruteforce-XML 단일 공격은 앞 5개 패킷에서 정상과 거의 완전히 구분된다(시간 분할 양방향). 단 이 데이터에서는 첫 패킷 길이 하나로도 구분되어 난이도가 낮다"까지다
5. 같은 구조의 한계: 공격자·피해자가 각 1개인 단일 테스트베드, 공격 한 종류, 모든 공격 플로우가 12개 이하

## 다음 단계 제안

- 더 어려운 평가가 되려면 공격이 다양해야 한다(Bruteforce-HTTPS, Probing, L7 DoS). 추가 데이터는 별도 결정 사항이다
- 식별력이 큰 첫 패킷 크기를 입력에서 가린 대조(예: `seq_0` 제외, 순서 섞기)로 "초반 패킷 순서가 얼마나 기여하는가"를 볼 수 있다. A의 순서 섞기와 같은 설계다
- A의 k 평가 결과와 경향을 비교한다. 단 A는 13종 다중 분류, B는 2종이라 절대 점수는 비교하지 않는다
