# 트랙 B pcap 추출기 (1단계)

HIKARI 원본 pcap에서 TCP 443 플로우를 조립하고, 플로우별 앞 30개 **페이로드 패킷**의 부호 있는 길이와 도착 시각을 만든다. 표준 라이브러리만 쓴다(`src/track_b/pcap_flows.py`). A 트랙의 시퀀스와 같은 정의라서 k별 결과를 A와 나란히 놓을 수 있다. 모델 학습·시간 분할 평가는 이 단계에 포함하지 않는다.

## 사양

| 항목 | 정의 |
|---|---|
| 입력 | classic libpcap(리틀엔디안, 마이크로초), 이더넷(+VLAN 한 겹), IPv4, TCP. 그 밖의 형식은 거부하거나 건너뛰고 건수를 기록한다 |
| 대상 플로우 | 서버 포트 443. 클라이언트 = 443이 아닌 쪽 |
| 플로우 키 | (클라이언트 IP, 클라이언트 포트, 서버 IP). 포트 재사용은 아래 경계 규칙으로 나눈다 |
| 플로우 경계 | 마지막 패킷 후 120초 경과, 또는 페이로드가 오갔거나 FIN/RST로 끝난 키에 SYN(ACK 없음)이 다시 오면 새 플로우 |
| 페이로드 패킷 | TCP 페이로드 길이 > 0. 길이는 IP 전체 길이에서 계산(이더넷 패딩 제외) |
| 방향 부호 | 클라이언트→서버 +, 서버→클라이언트 −. A 시퀀스와 같다(Malicious_TLS 첫 값은 정상 100%가 +) |
| 재전송 | 같은 방향에서 TCP 순서 번호(32비트 순환 비교)가 앞서지 않는 페이로드는 세지 않고 `retransmissions`에 집계 |
| 시퀀스 | 앞 30개 값, 뒤쪽 0 패딩(`trailing_zero_30`). k 평가는 앞 k개만 남기고 나머지를 0으로 만든다. 30칸 구조는 유지 |
| SYN 없이 시작 | `midstream=1`로 표시하고 제외하지 않는다 |
| 시간 | `t_i` = 플로우 첫 패킷 대비 i번째 페이로드 패킷의 경과 초 (조기 탐지 지연 측정용). 모델 입력이 아니다 |
| 라벨 | **캡처 파일이 곧 공격 유형**(plan.md). 공격자 103.255.15.23 → 피해자 128.199.242.104:443 = `bruteforce_xml`, 그 밖의 443 = `benign` |

식별자 컬럼(`client_ip`, `client_port`, `server_ip`, `pcap`, `day`, `flow_id`)과 시간 컬럼은 **모델 입력이 아니다**. 모델 입력은 `seq_0`~`seq_29`뿐이다. `flows.csv`는 `DATA_DIR/processed/track_b_<run-id>/`에만 저장하고 Git에는 집계(`prefix_report.csv`)와 메타데이터만 둔다.

## A와 맞춘 보고 계약

`prefix_report.csv`는 (캡처, 라벨)·k별로 `rows`, `reached_k_rows`, `short_rows`, `short_fraction`, `padding_policy`를 기록한다. A의 `docs/sequence_prefix_plan.md`와 같은 컬럼명이다. 도달 여부는 저장된 앞 30개가 아니라 **전체 페이로드 패킷 수**(`payload_packets`)로 판단하므로 30개를 넘는 흐름도 정확히 센다. 분모는 해당 (캡처, 라벨)의 전체 플로우 수다. 파티션(학습·시험)별 표는 시간 분할이 정해진 뒤 만든다.

"k번째 패킷 도달 시 판정"과 "짧은 흐름 종료 시 판정"은 다르다. 기본 성능표를 짧은 흐름 포함 전체 행으로 내더라도, 도달한 행만의 점수를 따로 낸다(A 계획과 동일).

## 해석상 주의

1. **HIKARI Bruteforce-XML 공격 플로우는 모두 12개 이하의 페이로드 패킷으로 끝난다.** k=20·30에서는 공격 행이 한 건도 k에 도달하지 못하므로 "k번째 패킷에서 판정"을 공격 클래스에 대해 평가할 수 없다. 의미 있는 k는 5·10이고, 20·30은 "끝난 흐름 전체를 본 평가"다. 이는 추출기 문제가 아니라 데이터의 성질이다
2. 공격 플로우의 길이가 거의 같아(중앙값 11 = p90 11) 단순한 패킷 수만으로도 정상과 갈릴 수 있다. 정상(중앙값 14, 긴 꼬리)과 분리되는지를 모델 성능과 별도로 확인해야 한다
3. 정상도 같은 클라이언트(103.255.15.23)에서 나오는 플로우가 많다. 라벨은 피해자 IP 기준이고, IP는 모델 입력에서 제외한다
4. SYN 없이 시작한 플로우가 13~17%다. 캡처 시작 전에 이미 열린 연결이거나 120초 경계로 나뉜 뒷부분일 수 있다. 제외하지 않았고 `midstream`으로 구분해 민감도를 볼 수 있다
5. 시퀀스 값의 최대 크기가 A(29,200)와 같은 규모인지, 캡처에 TSO/GRO가 섞였는지는 이번에 확인하지 않았다
