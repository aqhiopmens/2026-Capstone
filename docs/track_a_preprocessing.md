# 트랙 A 원본 재전처리 (2026-10-29)

캡디1 정제본 대신 `$DATA_DIR/raw/malicious_tls/malicious_TLS.csv`에서 시작한다. 이번 단계는 형식 변환, 품질 문제 격리, 클래스·분할 배정까지다. 모델 학습·특징 선택·스케일링은 하지 않는다.

## 입력과 처리

- 원본 92,034행, 23종, 특징 117개와 Label. 원본 체크섬은 결과 메타데이터에 기록했다
- 지문 9개 / 통계 78개 / 방향 부호가 있는 패킷 길이 시퀀스 30개를 명시적으로 구분한다
- TLS 지문 중 16진수 표현 7개 컬럼을 정수로 변환한다. `0`은 0으로 보존하고, 잘못된 토큰을 조용히 0으로 바꾸지 않는다
- 원본 데이터 레코드 순서에 0부터 시작하는 `source_row`를 붙인다. CSV의 헤더·물리적 줄 번호와 구분한다
- 통계 78개 중 음수값이 있는 9행은 `invalid`로 격리한다. 데이터 분위수나 라벨별 성능으로 정한 기준이 아닌 고정 유효 범위 검사다. 원본·변환본에서 행을 삭제하지 않으며 학습·평가 배정에서만 제외한다. 부호가 방향인 시퀀스의 음수는 정상이다
- 완전 중복 863행, 극단값, payload 지속시간 0인 4행은 유지한다. 0 지속시간만으로 오류라고 단정하지 않는다. 결측·무한값은 현재 원본에 없으며 추후 발견되면 자동 대체하지 않고 중단한다

행 보존과 모델 입력 적합성은 구분한다. 변환된 `features.csv`에는 모든 원본 행이 남아 있으므로 **파일 전체를 곧바로 학습하지 말고 반드시 `rows.csv`와 `splits.csv`로 대상 행을 선택**한다. `source_row`, Label, 패턴 ID와 배정값은 입력 특징이 아니다. 실제 입력 컬럼은 `feature_groups()`에 정의한 117개 또는 그 부분집합만 쓴다.

## 클래스 구성과 보류 검증

| 용도 | 클래스 수 | 행 수 |
|---|---|---|
| known: 학습·시험 대상 | 13 | 65,834 |
| unknown: 미확인 위협 보류 | 5 | 12,877 |
| excluded: 기존 설계의 패턴 부족 5종 | 5 | 13,314 |
| invalid: 음수 통계 품질 문제 | 위 클래스 중 3종 | 9 |

행 수 합계는 92,034다. `invalid`는 클래스 수에 더하는 새 클래스가 아니다. 학습 대상 13종은 정상 1종과 공격 12종이며, 제외 5종은 기존 설계대로 유지한다. 캡디1 정제본의 ‘완전 중복 0행’과 원본의 중복 863행은 서로 다른 입력에서 측정한 값이다.

보류는 nessus·arachni(스캐너), Totbrick·Tiggre·TrickBotCC(C&C)로 확정한다. 실제 코드에서는 원본의 전체 라벨명을 사용한다. 먼저 유효한 18종 전체를 알려진 클래스라고 가정해 그룹 분할 가능성만 진단했다. 이 진단 배정은 실제 학습에 사용하지 않는다.

| 후보 | 가상 학습 행 | 가상 시험 행 |
|---|---|---|
| nessus | 1,653 | 345 |
| arachni | 1,518 | 379 |
| Totbrick | 2,086 | 643 |
| Tiggre | 2,006 | 1,261 |
| TrickBotCC | 2,527 | 459 |

시드 0·1·2 모두 이 행 수이며, 각 30행 이상이다. 실제 분할에서는 이 5종 전부를 `unknown`에만 배정한다. 학습·알려진 클래스 시험에는 0행이며, 향후 문턱 조정용 검증셋에도 넣지 않는다. 보류와 known 사이의 시퀀스 패턴 겹침도 0건이다.

## 실제 분할

- 무작위: known 13종의 클래스 층화 80/20. 각 시드 학습 52,667행·시험 13,167행
- 패턴 그룹: 시퀀스 30개가 같은 행은 라벨과 무관하게 같은 그룹이다. int64 little-endian 바이트의 SHA-256을 패턴 ID로 삼고, 서로 다른 패턴이 같은 ID를 갖지 않는지도 검사한다
- 시드별 전역 그룹 ID 순서를 바꾼 후 StratifiedGroupKFold(5, shuffle=False)로 배정한다. 각 클래스의 학습·시험이 모두 30행 이상인 폴드 중 전체 시험 비율이 20%에 가장 가까운 것을 선택한다(동률은 폴드 번호순). 점수나 모델은 사용하지 않는다
- 최종 그룹 분할은 세 시드 모두 4번 폴드: 학습 52,828행·시험 13,006행(19.76%). 클래스별 최소 학습 886행·시험 221행, 학습 패턴과 시험·unknown 패턴의 겹침 0건
- 무작위 분할은 반복 패턴의 영향을 드러내는 대조 조건이다. 학습·시험의 패턴 겹침은 시드별 1,347 / 1,366 / 1,357개이며, 극단값·중복을 유지했으므로 누수가 통제된 분할로 주장하지 않는다
- 시드별 클래스 건수가 같아도 같은 시험 행을 뜻하지 않는다. 이후 실험에서 분할과 모델 시드를 동시에 바꾸면 두 변동의 기여를 분리할 수 없다

현재 train/test 배정만 만들었다. 미확인 위협 판정용 검증셋은 공통 코드 단계에서 **train 내부에서만** 떼어내고, 그룹 조건에서는 train/validation 패턴도 격리한다. 딥러닝용 스케일러·학습 기반 대체값·특징 선택이 필요해지면 검증셋을 분리한 최종 학습 부분에만 적합한다.

## 실행·산출물

```sh
uv run python -m unittest discover -s tests -p 'test_track_a_preprocess.py'
uv run python -m src.track_a.preprocess --run-id <날짜_실행식별자>
```

`DATA_DIR`, `MACHINE`이 필요하다. 은빈 맥은 `MACHINE=eunbin-mac`이며 `~/.zshrc`에 설정했다. 비대화형 셸에서는 해당 환경변수를 명시적으로 전달한다. 기존 run-id의 디렉터리는 덮어쓰지 않는다.

이번 데이터 파일은 `$DATA_DIR/processed/track_a_2026-10-29/`에 있다.

- `features.csv`: 117개 수치 특징 + Label + source_row, 원본 92,034행 보존
- `rows.csv`: 원본 행 번호·클래스·패턴 ID·용도(known/unknown/excluded/invalid)
- `splits.csv`: 원본 행 번호와 분할 종류·시드별 배정 6개(train/test/unknown/excluded/invalid)
- `invalid_rows.csv`: 품질 문제 9행의 원본 행 번호·라벨·패턴·제외 사유

Git에는 `outputs/results/preprocess_2026-10-29/`의 **집계만** 올린다: 클래스별 행·패턴 수, 분할별 행·패턴 수, 보류 후보 진단, 분할 요약, 원본 체크섬·정책·버전 메타데이터. 이는 모델 점수 CSV가 아닌 전처리 검증 기록이다.

검증은 합성 데이터 계약 검사 10개와 원본 전체 실행으로 수행했다. 저장한 파일을 재로딩하여 원본 형식 변환 값·행 순서·6개 분할 계약을 다시 검사했고 원본 체크섬이 바뀌지 않았음을 확인했다. 원본 데이터·행별 배정은 Git에 포함하지 않는다.
