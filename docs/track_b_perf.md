# B: 계획서 성능 목표 측정 (10MiB pcap 처리 시간, 플로우 1건 판정 지연)

계획서 최종목표의 "10MB 규모 pcap 30초 이내 처리, 플로우 1건당 판정 지연 10ms 이하"를 재었다(정확도는 재지 않음). 설계는 Slack 안건 7에서 결과를 보기 전에 고정했다.
코드 `src/track_b/perf_measure.py`, 주 결과 `outputs/results/track_b_perf_2026-11-05_win_v2/`. Windows(kyle-win, Intel 논리 CPU 8개, Python 3.12.14, 깨끗한 커밋 `17749fb`)와 Colab(CPU 2026.07, 논리 CPU 2개, Python 3.12.13, 소스 묶음 `676835d`)에서 측정했다. 시간 값은 환경 의존이다.
v1(`..._win_v1`)은 조립 1회를 8개 조합에 재사용하고 단계 시간을 더한 값이라 합의한 연속 측정과 달라 진단으로만 남겼다(범위 0.072~0.107초).

## 정의
- 모델: 2021 04-11 HTTPS(payload>0) 학습, RF 100그루·LightGBM 고정 설정, 시드 0, k=5·10, 입력 seq. 모델 학습은 측정 구간 밖.
- 목표 1: 각 pcap 앞부분을 패킷 경계에서 10MiB 이상이 되는 첫 지점에서 자른 시료 3개에 대해, 조합(모델·k·n_jobs)마다 **[파일 읽기 시작 → 플로우 조립 → payload 필터 → 특징 생성 → predict 종료]를 하나의 연속 타이머**로 잰다. 워밍업 1회 뒤 5회. 판정 = 시료별 5회 최댓값 ≤ 30초(중앙값은 참고). 단계별 시간(`runs.csv`)은 같은 실행의 체크포인트 차이로 진단용이다.
- 목표 2: 앞 k개 페이로드 패킷이 도달한 플로우 하나의 [특징 벡터 생성 + 단건 predict(스레드 설정 n_jobs=1)]. 패킷 도달 대기와 pcap 파싱은 제외하고 따로 적는다. 도달 플로우가 1,000개 미만이라 3개 시료의 전수를 썼다(k=5 n=309, k=10 n=277). 판정 = p95 ≤ 10ms, 최댓값·10ms 초과 건수 기록. 행별 측정(플로우 식별자·단건 ms·도달 대기 초)은 `DATA_DIR/perf_runs/`에 두고 Git에는 SHA만 기록했다.

## 결과 (Colab CPU 2026.07, `outputs/results/track_b_perf_2026-11-05_colab/`)
같은 코드·같은 시료 SHA·같은 판정 기준. 로컬 디스크로 복사한 뒤 측정했고 Drive→로컬 복사 2.86초는 측정 밖이다. 결과 zip SHA-256 `2d057c33…46b7`(Drive `colab_exports/perf_2026-11-05_colab`).
- 목표 1: 8개 조합 × 시료 3개 모두 5회 **최댓값 0.076~0.265초**(중앙값 0.072~0.186초). 30초 한도 대비 약 1/110 이하(통과).
- 목표 2 (도달 플로우 전수, k=5 n=309 / k=10 n=277):

| 모델 | k | 중앙값 ms | p95 ms | p99 ms | 최댓값 ms | 10ms 초과 | 판정 |
|---|---|---|---|---|---|---|---|
| RF | 5 | 9.08 | 10.81 | 15.08 | 15.68 | 31 | **미달** |
| RF | 10 | 9.29 | 15.75 | 17.45 | 19.28 | 68 | **미달** |
| LightGBM | 5 | 1.79 | 2.79 | 2.97 | 76.58 | 1 | 통과 |
| LightGBM | 10 | 2.64 | 3.24 | 4.48 | 5.45 | 0 | 통과 |

- **RF는 Colab(논리 CPU 2개)에서 p95 10ms 기준을 넘었다**(Windows 논리 CPU 8개에서는 통과). 같은 모델·같은 시료에서 나온 환경별 관측 차이이며 CPU 성능·코어 수·소프트웨어 등 요인은 분리하지 못했다. 원인 분해(DataFrame 생성 대 predict, 트리 수)는 하지 않았고, 사전 합의대로 모델 구성은 결과를 보고 바꾸지 않았다. 경량화(트리 수 축소, 배열 입력 등)는 이 수치와 분리된 후속 측정으로 다룬다.
- LightGBM k=5의 최댓값 76.58ms는 10ms 초과 1건의 이상치이며 p95·p99는 낮다(원인은 확인하지 않음).
- 패킷 도달 대기는 Windows와 동일한 트래픽 값이다(k=5 중앙값 0.22초, k=10 0.44초).

## 한계
- 시료가 3개 pcap의 앞부분 10MiB뿐이고 payload>0 플로우가 81~133개로 적다. 플로우가 많은 트래픽에서는 시간이 달라질 수 있다.
- 단건 시간은 DataFrame 생성을 포함한 파이썬 호출 지연이며 서비스 지연(대시보드·네트워크·직렬화)은 측정하지 않았다. 환경별 한 번의 실행이다.
- 단건 판정은 n_jobs=1(단일 스레드) 기준이고, 10MiB 일괄 판정은 n_jobs=1과 -1을 모두 측정했다. 병렬화나 경량화 개선은 하지 않았다. 10MiB 처리 목표는 두 환경에서 충족했고, 플로우 1건 10ms 목표는 Windows에서 모두 충족, Colab에서는 LightGBM만 충족하고 RF는 미달이다.
