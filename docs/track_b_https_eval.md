# 트랙 B HIKARI Bruteforce-HTTPS 앞 k개 평가 (04-11 ↔ 04-16)

캡처 단위 **잠정 라벨**(공격자 → 피해자:443 = 공격, 그 밖의 443 = 정상)을 예측하는 **탐색 평가**다. 실제 공격 정답 검증, 일반화 증거, 실시간 지연의 근거가 아니다. 라벨 감사 [PR #34](https://github.com/aqhiopmens/2026-Capstone/pull/34) 결과(공격 CSV 상충 다수, 정상 미매칭 04-11 65.8%)가 그대로 한계다.

## 조건

| 항목 | 내용 |
|---|---|
| 데이터 | `track_b_https_2026-11-02_v1/flows.csv`(04-11 4,596, 04-16 33,560 플로우)와 감사 `flow_status.csv`. 학습 전 SHA-256을 metadata와 대조 |
| 방향 | 04-11→04-16, 04-16→04-11 (시간 분할) |
| 범위 | `all`(공격 전 피해자) / `only_242104`(공격이 .242.104인 플로우만; 피해자·날짜 교락 통제) |
| 제외 | payload 0 플로우(04-11 정상 57, 04-16 정상 359·공격 2)는 두 범위 모두 평가에서 제외하고 `payload0_excluded.csv`에 개수를 둠 |
| 입력 | `seq`(앞 k개 시퀀스), `counts`(앞 k개에서 계산한 4개 요약). k = 5·10·20·30 |
| 모델·시드 | RF·LightGBM 고정 설정, 시드 0·1·2. 2×2×4×2×2×3 = **192회** |
| 부분집합 | 같은 저장 시험 예측에서 계산(추가 학습 없음): `reached_k`, `short`, `not_midstream`, `benign_csv_confirmed`, `benign_csv_unmatched`, `attack_242104`, `attack_88_81`. 한 클래스가 없으면 macro-F1을 비움 |
| 재현 | `uv run python -m src.track_b.https_eval --flows-run-id 2026-11-02_v1 --audit-run-id 2026-11-02_v2 --run-id <ID>`. 결과 `outputs/results/track_b_https_eval_2026-11-02_v2/`, 행별 예측은 DATA_DIR |

## 결과 (macro-F1 3시드 평균, 시험 행에 상한 없음)

| 분할 | 입력 | 모델 | k=5 | k=10 | k=20 | k=30 |
|---|---|---|---|---|---|---|
| 04-11→04-16 전체 | seq | RF | .685 | .685 | .684 | .685 |
| 04-11→04-16 전체 | counts | RF | .685 | .684 | .675 | .675 |
| 04-11→04-16 .242.104만 | seq | RF | .999 | .999 | .999 | .999 |
| 04-11→04-16 .242.104만 | counts | RF | .998 | .998 | .980 | .979 |

| 04-16→04-11 전체 | counts | RF | .818 | .985 | .821 | .791 |

LightGBM과 전체 표는 `summary.csv`. 정상 specificity(CSV 일치 24,186·1,409, 미매칭 3,529·2,730)는 대부분 0.998~1.000이다. 이 부분집합은 FPR·specificity와 분모만 읽고 공격 recall·전체 macro-F1의 대체 검증으로 쓰지 않는다.

## 읽는 법과 확인한 점

1. **04-11→04-16 전체의 0.685는 k와 무관하다.** 공격 .88.81(3,951개) recall이 0.000이고 .242.104 공격(1,533개)은 0.997이다. 04-11 학습에는 .88.81이 없어서 새 피해자 패턴을 못 잡는 것이며, 앞 k개 정보 부족이 아니다. 같은 방향 `only_242104`에서는 0.999다. 단, 날짜와 피해자가 같이 바뀌므로 둘 중 무엇이 원인인지는 이 설계로 가려지지 않는다.
2. **04-16→04-11 `only_242104` seq의 낮은 점수**(k=5 공격 recall 0.5): 04-11 공격 앞 5개 값 중 04-16 학습 공격에도 있는 것은 50%다(반대 방향 99.7%). 04-11에는 첫 패킷 304·`-55` 계열이 있고 04-16 공격은 거의 첫 패킷 308이다. 날짜가 바뀌면 같은 공격의 패킷 크기가 몇 바이트 달라지고, 학습에 없던 정확한 값은 못 맞힌다. k=10·20은 겹침이 49.5%·31.8%.
3. **counts k=10만 .999인 것**: 앞 10개 길이 합이 공격은 4,392~4,635에 거의 고정이다(중앙값 04-11 4,425, 04-16 4,423). k=5·20에서는 이 대역이 날짜 간에 어긋나거나 정상과 겹친다. 고정 크기 요청을 반복하는 공격의 지문이며 조기 탐지 능력이 아니다.
4. 높은 점수(0.997~0.999)는 고정 크기 요청을 반복하는 공격이라 쉽다는 뜻이다. 모델 한계는 날짜 간 정확한 값 변화(2)와 새 피해자(1)에서 드러난다.

## 한계

- 라벨은 잠정 캡처 규칙이다. 공격 04-16 .88.81은 CSV와 상충(Bruteforce+Benign 짝 행)이라 확인 불가, 정상 04-11은 65.8%가 CSV 미매칭이다.
- 날짜·피해자 교락. 04-11 공격은 .242.104 하나, 시험 공격이 400개뿐인 방향이 있다.
- 시드는 모델 시드만 바꾸고 분할은 날짜라 고정이다. 두 pcap만 쓴 결과이며 환경(Mac/Colab) 교차 재현은 하지 않았다.
- 실행 환경은 김강민 Windows 로컬이며 최종 수치로 확정하려면 Mac 독립 재계산이 필요하다.
