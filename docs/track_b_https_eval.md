# 트랙 B HIKARI Bruteforce-HTTPS 앞 k개 평가 (04-11 ↔ 04-16)

캡처 단위 **잠정 라벨**(공격자 → 피해자:443 = 공격, 그 밖의 443 = 정상)을 예측하는 **탐색 평가**다. 실제 공격 정답 검증, 일반화 증거, 실시간 지연의 근거가 아니다. 라벨 감사 [PR #34](https://github.com/aqhiopmens/2026-Capstone/pull/34) 결과(공격 CSV 상충 다수, 정상 미매칭 04-11 65.8%)가 그대로 한계다.

## 조건

| 항목 | 내용 |
|---|---|
| 데이터 | `track_b_https_2026-11-02_v1/flows.csv`(04-11 4,596, 04-16 33,560 플로우)와 감사 `flow_status.csv`. 학습 전 SHA-256을 metadata와 대조 |
| 방향 | 04-11→04-16, 04-16→04-11 (시간 분할) |
| 범위 | `all`(공격 전 피해자) / `only_242104`(공격이 .242.104인 플로우만; 피해자·날짜 교락 통제) |
| 제외 | payload 0 플로우(04-11 정상 57, 04-16 정상 359·공격 2)는 두 범위 모두 평가에서 제외하고 `payload0_excluded.csv`에 개수를 둠 |
| 입력 | `seq`(앞 k개 시퀀스), `counts`(앞 k개에서 계산한 4개 요약). k = 5·10·20·30 |
| 모델·시드 | RF·LightGBM 고정 설정, 시드 0·1·2. 2×2×4×2×2×3 = **192회** |
| 부분집합 | 같은 저장 시험 예측에서 계산(추가 학습 없음): `reached_k`, `short`, `not_midstream`, `benign_csv_confirmed`, `benign_csv_unmatched`, `attack_242104`, `attack_88_81`. 한 클래스가 없으면 macro-F1을 비움 |
| 재현 | `uv run python -m src.track_b.https_eval --flows-run-id 2026-11-02_v1 --audit-run-id 2026-11-02_v2 --run-id <ID>`. 결과 `outputs/results/track_b_https_eval_2026-11-02_v2/`, 행별 예측은 DATA_DIR |

## 읽는 법과 확인한 점

아래는 모두 **관찰**이며 원인은 확정하지 않았다. 날짜·피해자·패턴 겹침과 점수가 함께 움직인다는 것까지만 말한다.

1. **04-11→04-16 전체의 0.685는 k와 무관하다.** 공격 .88.81(3,951개) recall이 0.000이고 .242.104 공격(1,533개)은 0.997이다. 04-11 학습 공격은 .242.104뿐이다. 같은 방향 `only_242104`에서는 0.999다. 날짜와 피해자가 같이 바뀌므로 점수 하락이 피해자 때문인지, 이 피해자 플로우의 패턴 차이(payload 중앙값 22 대 52~53) 때문인지는 이 설계로 가려지지 않는다.
2. **04-16→04-11 `only_242104` seq의 낮은 점수**(k=5 공격 recall 0.5): 04-11 공격 앞 5개 값 중 04-16 학습 공격에도 있는 것은 50%다(반대 방향 99.7%). 04-11에는 첫 패킷 304·`-55` 계열이 있고 04-16 공격은 거의 첫 패킷 308이다. 학습에 없던 값 조합이 많을수록 recall이 낮은 방향과 일치하지만, 값 겹침이 원인이라는 것은 검증하지 않았다(겹침만 바꾼 통제 실험 없음). k=10·20의 겹침은 49.5%·31.8%인데 seq recall은 k가 커질수록 오히려 높아지는 구간이 있어 겹침만으로 점수가 설명되지는 않는다.
3. **counts k=10만 .999인 것**: 분모는 방향 04-16→04-11, 범위 `only_242104`, 공격은 .242.104 플로우(payload>0) 04-11 400개·04-16 1,533개, 정상은 04-11 4,139개·04-16 27,715개다. 앞 10개 길이 합의 10~90분위가 공격은 4,392~4,635이고 중앙값은 04-11 4,425, 04-16 4,423이다. k=5·20에서는 같은 대역의 날짜 간 차이가 더 크거나 정상과 겹치는 구간이 있다(k=20 04-16 .242.104 공격 10~90분위 12,345~19,099 대 04-16 정상 4,656~41,926, 04-11 정상 24~37,494). 공격 요청 크기가 거의 일정하다는 관찰이며, 조기 탐지 능력의 근거가 아니다.
4. 높은 점수(0.997~0.999)는 이 공격 플로우가 길이 합·시퀀스로 쉽게 구분된다는 관찰이며 일반 성능 주장이 아니다. 낮아지는 곳은 위 1·2번 조건(새 피해자 포함 시험, 날짜 간 값 변화)이다.

## 한계

- 라벨은 잠정 캡처 규칙이다. 공격 04-16 .88.81은 CSV와 상충(Bruteforce+Benign 짝 행)이라 확인 불가, 정상 04-11은 65.8%가 CSV 미매칭이다.
- 날짜·피해자 교락. 04-11 공격은 .242.104 하나, 시험 공격이 400개뿐인 방향이 있다.
- 시드는 모델 시드만 바꾸고 분할은 날짜라 고정이다. 두 pcap만 쓴 결과이며 환경(Mac/Colab) 교차 재현은 하지 않았다.
- 이 수치는 김강민 Windows 로컬 예비 결과이다. Mac 저장 예측 독립 재계산(예측 3,433,200행, 192회 점수·부분집합)은 집계 검증이며 불일치 0건이다. 모델 학습·예측 생성의 교차 환경 재현은 하지 않았고 Colab 최종 실행과도 구분한다(최종 수치는 Colab이라는 기존 원칙).
