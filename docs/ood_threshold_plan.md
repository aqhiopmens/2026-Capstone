# 트랙 A 미확인 판정 문턱 평가 — 실행 계획 초안

2026-10-31 서은빈이 **계획 준비와 교차 검토 보완 반영을 승인**했다. 이 문서는 기존 RF 최대 예측확률·알려진 검증 거절률 5% 원칙의 세부 제안이다. **구현·모델 학습·문턱 선택·시험 평가는 아직 착수하지 않았으며, 계획 확인 후 별도 승인을 받는다.**

## 질문과 범위 제안

질문은 “학습에 없던 보류 5종을 RF의 낮은 최대 예측확률로 거절할 수 있는가, 그때 알려진 13종을 얼마나 함께 거절하는가”다. 미확인 거절은 악성 판정이나 보류 5종의 종류 식별과 구분한다.

| 항목 | 제안 |
|---|---|
| 모델 | 공통 RF 고정 설정: 100 trees, balanced, workers=2. 파라미터 탐색·확률 보정 없음 |
| 특징 | 전체 117개 / 원순서 시퀀스 30개, 두 입력을 사전에 고정 |
| 이유 | 전체 특징의 미확인 거절 기준선과 패킷 시퀀스만의 결과를 함께 확인. 보류 성능을 보고 입력을 고르지 않음 |
| 분할·시드 | 기존 random / pattern_group, 시드 0·1·2 모두 유지 |
| 신규 학습 | 2입력 × 2분할 × 3시드 = **환경당 12회**, 맥 예비12 + Colab 최종12 = 총24회 |
| 이번 제외 | LightGBM·CNN·LSTM, 지문/통계 단독 추가 학습, k5/10/20별 문턱, 문턱의 B 데이터 직접 이식 |

전체117개는 흐름 통계·지문까지 포함하고 시퀀스30개는 최대30개 패킷이다. 동일 관측 시간의 조기 탐지 비교로 설명하지 않는다. 두 입력은 아직 승인 전인 범위 제안이며 결과를 본 뒤 유리한 조건만 남기지 않는다.

## B 추가 데이터 조사와의 관계

이 계획은 기존 **Malicious_TLS**의 known13종·보류5종을 사용하는 A 실험이다. B의 HIKARI HTTPS 04-11·04-16 확보·피해자 라벨 정정과 독립적으로 준비·구현할 수 있으며 추가 다운로드를 기다리지 않는다. B 자료를 이번 fit·validation·test·unknown에 넣지 않고 A 보류 구성도 바꾸지 않는다. A에서 얻은 문턱을 B에 그대로 적용하지 않는다. B 조사 결과와의 경향 비교·공통 API 계약 확인은 별도 범위다.

## 데이터·검증 분리

- 기존 원본 재전처리 `preprocess_2026-10-29`의 known13종 65,834행, unknown5종 12,877행과 외부 분할6개를 유지한다. 원본·역할·제외/invalid 배정도 바꾸지 않는다
- 보류는 nessus·arachni·Totbrick·Tiggre·TrickBotCC이며 코드의 전체 라벨명을 사용한다. 보류5종은 fit·문턱 선택·특징/설정 선택에 넣지 않는다
- 기존 `split_validation()`으로 **외부 train 내부의 약20%만** validation으로 분리한다. random은 층화, pattern_group은 원본30개 패턴을 train/validation/test/unknown 사이에 격리한다
- 그룹 검증 폴드 선택은 기존 규칙(클래스별 train/validation 최소30행, 목표20%와 차이·폴드 순서)에 따른다. 점수로 폴드·시드를 고르지 않는다. 같은 split/seed의 두 특징군은 같은 행 배정을 쓴다
- 실제 최종 train만 fit하고 validation 예측으로 문턱을 고정한다. 이후 validation을 train에 합쳐 재학습하지 않는다
- **이전 #15·#26 모델/예측을 문턱 선택용으로 재사용하지 않는다.** 그 모델은 외부 train 전체를 학습해 새 validation 행을 이미 보았다. 같은 원본·외부 배정만 재사용하고 새로12회 학습한다

계획 단계에서 기존 분할 함수만 호출한 읽기 전용 사전 점검 결과다. 모델 fit·새 예측·문턱 계산은 없었다.

|---|---|---|---|---|---|
| random 0/1/2 각각 | 42,133 | 10,534 | 13,167 | 12,877 | 526 |
| pattern_group 0/1 각각 | 42,020 | 10,808 | 13,006 | 12,877 | 540 |

random과 pattern_group은 기존 설계대로 **주·보조가 아닌 대조 조건**으로 같은 표·정책에 모두 보고한다. 원본30개 시퀀스의 pattern_id로 최종 train 사전을 만들고 validation/test/unknown 각각에 대해 학습과 패턴이 같은 행 수·비율, 고유 패턴 수·겹친 패턴 수를 전체 및 라벨별 분모와 함께 감사한다. pattern_group의 겹침0은 계약 검사이며 random의 겹침은 삭제하지 않는다. 이 감사로 평가 조건을 설명하되 점수나 겹침 비율을 보고 분할을 재선택하지 않는다. τ가1에 가깝다는 사실만으로 unknown 거절률이 낮다고 예측하지 않는다.

## 문턱·동률 규칙

RF가 알려진13종에 대해 내는 확률의 최댓값을 `s(x)`로 두고, **`s(x) < τ`일 때만 `__unknown__`으로 거절**한다. `s(x) == τ`는 기존 예측 클래스로 수용한다. RF의 predict_proba는 각 트리의 클래스 확률을 평균한 값이므로 이를 실제 악성 위험도나 보정된 신뢰도로 부르지 않는다([sklearn 1.6 RF 설명](https://scikit-learn.org/1.6/modules/generated/sklearn.ensemble.RandomForestClassifier.html)).

주 결과의 목표 거절률은 `α=0.05`다. 각 입력·split·seed·환경에서 validation의 알려진 **전체 행**을 분모로 하고 클래스 빈도 가중 없이 아래 절차를 따른다(각 행의 가중치1, 클래스별5% 보장은 없음).

1. validation 최대확률의 유일값들과 0을 후보 문턱으로 만든다. 비어 있거나 범위를 벗어난/비유한 확률이면 중단한다
2. validation 행 수 `n`에 대해 허용 거절 수를 `floor(α×n)`으로 정한다(5%는 정수 연산 `n×5//100`)
3. 후보 중 `count(s_val < τ) <= floor(α×n)`을 만족하는 **가장 큰 τ**를 선택한다. 모델·보류 성능으로 후보를 고르지 않는다
4. 동률을 일부만 거절하거나 난수·행 ID로 갈라 정확히5%를 맞추지 않는다. 실제 검증 거절률이5%보다 작아도 그대로 보존한다
5. 보간·확률 반올림 없이 원래 float와 strict `<`를 사용한다. 저장/복원은 round-trip 정밀도로 하고 τ·허용 수·실제 거절 수/비율·경계 동률 수를 기록한다

예를 들어 validation이 전부 같은 점수라면 해당 점수를 문턱으로 정해 검증 거절0행이 될 수 있다. 이것은 실패를 숨기지 않고 문턱의 분해능 한계로 보고한다. **검증의5% 상한은 알려진 시험 거절률5%를 보장하지 않는다.** 시험에서 더 많이 거절돼도 사후 조정하지 않는다.

민감도는 사전 고정한 α=1%·10%도 같은 저장 validation 점수에서 계산해 모두 보고한다. 추가 fit은 없고 이 결과로 주 α를 변경하지 않는다. 비교용 **무거절 정책 τ=0**도 같은 새 모델의 저장 점수에 적용한다. 이는 α=0 검증 분위수 정책과 구분한다.

따라서 환경당 fit은12회, 주5% 평가12건, 민감도24건, 무거절12건으로 **정책별 평가48건**이다. 알려진13종의 문턱 전 닫힌집합 점수는 모델당 한 번만 계산해12건이다.

### 최대확률 분포 감사

RF 점수가 항상0.01 단위라고 가정하지 않는다. 리프의 클래스 비율을 평균하는 RF에서 실제 분해능·분포는 저장 점수로 확인한다. 입력·분할·시드별 validation 점수의 행 수·유일값 수·최솟값/최댓값·1/5/50/95/99백분위·`s==1.0` 비율을 남기고, 각 정책의 허용 거절 수·실제 거절 수/비율·τ 경계 동률 수와 함께 보고한다. 감사용 분위수는 보간 방식도 기록하며 문턱 후보로 사용하지 않는다.

validation 감사와 τ 고정을 마친 뒤 test/unknown에도 같은 분포 감사를 적용한다. 시험·보류 분포를 보고 τ·α·입력·설정을 바꾸지 않는다. 1/5/10% 정책의 거절률-탐지율 표와 AUROC는 기술용이며 성능이 좋은 정책을 사후 선택하는 근거로 쓰지 않는다.

## 최종 평가와 지표

문턱을 고정한 후 기존 known test와 보류 unknown만 최종 지표 계산에 쓴다. validation에서는 정책 선택과 그 달성률만 기록하며 시험 성능으로 합쳐 보고하지 않는다.

| 질문 | 지표·분모 |
|---|---|
| 알려진 클래스를 얼마나 거절하나 | known test 거절 행/전체 known test 행, 클래스별13종의 거절률·support |
| 보류를 얼마나 거절하나 | 전체 unknown 거절률과 보류5종 각각의 거절률·support, 5종 거절률의 비가중 평균 |
| 정상에 주는 영향 | benign의 미확인 거절률과 알려진 악성 클래스로 오분류한 비율을 별도 기록 |
| 원래 분류 성능 | 같은 새 모델의 문턱 전 known13종 macro-F1·accuracy·13×13 혼동 행렬 |
| 분류와 거절을 함께 보면 | known13종+`__unknown__`의 고정14종 macro-F1·accuracy·14×14 혼동 행렬. 실제 보류5종은 이 표에서만 unknown 하나로 합치고 5종별 거절표는 유지 |
| 수용된 known 행의 품질 | 수용 known의 accuracy와 coverage·support를 함께 표시. 수용0행이면 accuracy=NA |
| 문턱과 무관한 점수 분리 | 보조 AUROC: unknown=1, known test=0, 점수 `1-s(x)`. 이 AUROC로 τ·α·특징을 선택하지 않음 |

AUROC는 binary indicator와 연속 점수를 받는 [sklearn 1.6 roc_auc_score](https://scikit-learn.org/1.6/modules/generated/sklearn.metrics.roc_auc_score.html)를 사용한다. 시험의 known/unknown 혼합 비율과 행 수를 함께 기록하며 이 구성의 precision·accuracy를 운영 환경 발생률로 확대하지 않는다. 무거절 정책도 연속 점수의 AUROC는 같은 값이므로 정책 성능과 중복 근거로 세지 않는다.

support=0 비율/recall과 빈 집합 점수는 NA, support1~29는 값·분모를 유지하고 low_support로 표시한다. 고정 클래스 macro-F1의 zero_division=0 정책과 클래스 구성은 함께 적는다. 각 정책·특징·분할의 시드0/1/2 값과 평균·표본편차를 모두 보고한다. 세 시드는 같은 보류 행을 사용하고 known test도 서로 겹치므로 독립 신뢰구간으로 해석하지 않는다.

### 보류 패턴에 같은 가중치를 주는 보조 지표

주 결과는 행 단위 거절률이다. 반복 패턴의 영향을 보기 위한 보조 지표의 키는 두 특징군 모두 기존 **원본30개 시퀀스의 pattern_id**로 고정한다. 보류 라벨 c마다 고유 패턴 집합 G_c를 만들고, 각 패턴 g에서 `r_g = 거절된 행 수 / 그 패턴의 전체 행 수`를 구한 뒤 `R_c = mean(r_g for g in G_c)`로 계산한다. 5종 전체 보조 요약은 R_c의 비가중 평균이다.

패턴별 any/majority 여부로 이분화하지 않는다. 전체117개 입력은 동일 시퀀스라도 다른 특징이 달라 거절 결과가 섞일 수 있으므로 패턴별 행 거절 비율을 그대로 보존한다. 라벨·패턴별 행 수/거절 수·비율, 라벨별 고유 패턴 수와 전체 행 수를 함께 기록한다. 클래스 사이 같은 pattern_id가 있어도 `(보류 라벨, pattern_id)`별로 계산한다. 원본 시퀀스 패턴을 기준으로 한 보조 분석이며 전체117개 입력의 완전 동일 패턴이라는 뜻은 아니다. 이 표를 문턱 선택이나 보류 구성 변경에 사용하지 않는다.

실행 예시 ID는 `ood_threshold_<날짜시각>_<환경>`이며 기존 ID는 덮어쓰지 않는다. workflow 필수 컬럼에 feature_group·policy_id·target_reject_rate·실제 거절률·분모를 보탠다. 서로 다른 정책을 섞어 평균하지 않는다.

- Git 배치 집계: 모델12건의 closed_set_metrics/confusion, policies48건의 threshold_metrics·open_set_confusion, thresholds36건(1/5/10%), known/unknown 클래스별 거절표, AUROC12건, 정책별3시드 요약, 무거절 대비 짝 차이, 원본 패턴 겹침·점수 분포 감사, 보류 라벨/패턴별 거절표·패턴 동일가중 보조 요약
- provenance: 기존 입력·외부/검증 배정 SHA, 코드·검증기 SHA, 모델 설정·행 수·환경/패키지 버전, 문턱 후보/동률 규칙, 실행 커밋·dirty 상태, 12개 실행 메타데이터를 배치에 보존
- DATA_DIR만: validation/test/unknown의 row_id·실제 라벨·문턱 전 예측 클래스·최대확률과 **13종 전체 확률 벡터**, 전체 행의 최종 배정. 확률 컬럼은 메타데이터의 `model.classes_` 순서와 일대일 대응시키고 값은 반올림하지 않는다. 같은 fit 모델에서 수집하며 추가 학습은 없다. 정책별 거절은 고정된 τ로 재구성하고 필요하면 별도 파생 파일로 저장한다
- 확률 계약: 고유 행 ID·분할·클래스 순서·13컬럼·유한한 [0,1] 값·행별 합1(허용오차1e-12)을 검사한다. 벡터의 max와 저장 최대확률, classes_ 순서의 argmax와 저장 예측 라벨도 대조한다. 원래 float의 round-trip 저장/복원을 검사하고 문턱 비교 전에 반올림하지 않는다. 엔트로피·마진은 이번 점수/정책으로 추가하거나 시험·보류에서 사후 선택하지 않는다
- 공유 파일은 저장 시점의 **원본 바이트 SHA-256과 파일 크기**를 메타데이터에 기록해 독립 검증자가 예측(전체 확률 포함)·assignments를 각각 대조할 수 있게 한다. 텍스트 CRLF→LF 정규화 SHA는 규칙을 명시한 별도 값이며 원본 SHA를 대체하지 않는다. 이진 파일은 정규화하지 않는다. 공유 Drive 경로도 전달하고 과거 미기록 파일의 사후 해시를 실행 당시 증명으로 쓰지 않는다
- 중단 시 completed_models·정책 평가 건수를 분리해 incomplete로 보존한다. 모든12개 모델과48개 평가·검증이 성공한 뒤에만 complete=true로 기록
- 코드는 `src/track_a/`의 전용 실행기·문턱/평가·검증 모듈로 작성하고 공통 RF·분할·저장 API를 재사용한다. 전체 확률은 반환된 모델을 사용하는 A 전용 어댑터에서 수집할 수 있는지 먼저 확인하며, 공통 API 변경이 필요하면 A·B 양쪽 검토를 받는다. `.py`가 공유 로직이며 개인 Colab 노트는 실행기 호출만 담당한다

## 승인 후 구현·검증 순서

6. Colab 검증기는 원본·저장 배정·validation 점수에서 τ를 새로 고르고, known/unknown 지표·행렬·시드 집계·무거절 짝 차이·점수 분포·패턴별 보조 지표를 독립 재계산한다. 전체 확률 벡터·입력/행별 파일 SHA와 실제 배정도 대조한다. unknown은 평가 단계에서만 읽어 문턱 산출 경로와 구분한다

## 주장 한계

검증 거절률을 통제해도 미확인 탐지율이 높다는 보장은 없으며, RF가 미지 입력에 높은 점수를 낼 가능성도 평가 결과에 남긴다. 보류5종은 사람이 고른 고정 구성이고, 알려진 시험은 앞선 실험에도 사용한 같은 행이다. 새로운 독립 데이터·모든 미지 공격에 대한 보편적 탐지나 운영 오탐 보장으로 설명하지 않는다.

실험 결과를 보고 τ·α·모델·보류 구성을 다시 고르면 새로운 탐색 실험으로 표시해야 한다. 이번 계획은 그런 사후 선택을 포함하지 않는다.
