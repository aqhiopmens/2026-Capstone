# B: 4클래스 PoC와 공격 하나 빼기 (안건 9)

정상 / Probing / Bruteforce-XML / Bruteforce-HTTPS 4클래스로 확장하고, 공격 유형 하나를 학습에서 뺐을 때의 경보율을 본다. PoC이며 캡처 단위 잠정 라벨, Windows 탐색 결과다. 코드 `src/track_b/https_probing.py`(Probing 추출·감사), `src/track_b/four_class.py`(평가), 결과 `outputs/results/track_b_https_probing_2026-11-08_v1/`, `track_b_four_class_2026-11-08_v1/`(본 평가, Python 3.12.14 / scikit-learn 1.6.1) · `track_b_four_class_2026-11-08_v2/`(**같은 입력·분할·하이퍼파라미터, 다른 패키지 환경의 별도 재실행**: Python 3.14.3 / scikit-learn 1.8.0 / numpy 2.4.3 / pandas 3.0.1. 공격 하나 빼기 행별 예측 저장). v2는 기존과 같은 환경·같은 코드의 재현이라고 읽지 않는다. 점수 24개, 혼동 384개, 경보 집계 144개는 v1과 수치가 같았다.

## 데이터와 라벨 (성능 확인 전 고정)
- Probing: HIKARI SCANCMS `Sunday_2021-05-02_1206.pcap`(2,308,628,480 B, md5가 Zenodo 값과 일치)에서 443 플로우 44,029개(payload>0: probing 38,168 + 정상 5,861). 규칙: 공격자 103.255.15.150 → 피해자 128.199.242.104:443 = probing, 그 밖의 443 = 정상.
- **CSV로 라벨이 확인되지 않는다.** 키+페이로드 수가 일치하는 probing 플로우 중 CSV가 Probing 한 범주만 가리키는 경우는 0건이다(단일 행이 Benign 10,148, Probing과 Benign 행이 섞인 경우 27,995, 미매칭 25). 같은 공격자→피해자 쌍의 CSV Benign 행이 61,556개이다. 라벨은 캡처 단위 규칙에만 의존한다(HTTPS·XML brute-force도 짝 행 구조지만 probing에서 더 심하다).
- 도달 비율(`reach_by_class.csv`): probing은 k=5 100%, k=10 약 85%, k=20 이상은 2% 미만이라 k=20·30은 제외하고 k=5·10만 쓴다.

## 4클래스 결과 (RF·LightGBM, 시드 3, k=5·10)
| 입력 | k | macro-F1 전체 시험 | macro-F1 새 피해자 .88.81 제외(C1 같은 분포) |
|---|---|---|---|
| 원본 seq | 5 | 0.845 | 0.9995 |
| 원본 seq | 10 | 0.845 | 0.9994 |
| 앞 3칸 마스킹 | 5 | 0.818 | 0.9654 |
| 앞 3칸 마스킹 | 10 | 0.844 | 0.9986 |
- 전체 시험의 0.845는 새 피해자 .88.81 3,951행이 전부 정상으로 판정(recall 0)되어서 생긴 값이다(마스킹 k=5만 198행이 XML로 분류). 이 행을 빼면 **원본 seq에서는** 4클래스 macro-F1이 0.999 이상이다(k=5 0.9995, k=10 0.9994). 앞 3칸 마스킹 k=5는 0.9654로 이보다 낮다. 새 피해자 일반화 실패는 4클래스에서도 같다.
- 클래스별 recall(RF, k=10, 원본): 정상 1.000, probing 1.000, XML 1.000, HTTPS(.242.104) 0.996, HTTPS(.88.81) 0.000. 클래스별 점수·혼동 행렬은 `metrics.csv`·`confusion.csv`, 출처별은 `by_source.csv`.
- **쉬운 구분 단서**: 각 공격 유형이 서로 다른 도구·서버·캡처에서 나왔고 정상의 출처가 곧 캡처라, 유형 구분과 캡처 구분이 분리되지 않는다. 높은 점수는 분류 능력의 일반 근거가 아니다. Probing은 CSV로 확인되지 않은 잠정 라벨이다.

## 공격 하나 빼기 (미학습 유형의 경보율 = 정상이 아니라고 판정한 비율, 시드 평균)
행별 예측을 `DATA_DIR/predictions/track_b_four_class_2026-11-08_v2/holdout_predictions.csv.gz`(SHA는 `metadata.json`)에 저장했고, 경보 건수·정상 오탐 건수를 거기서 독립 재계산해 `hold_out_alert.csv`와 72개 조건 모두 일치했다(`hold_out_counts.csv`). v1은 예측을 저장하지 않아 독립 재계산이 안 됐고, v2는 같은 사전 설정(코드·시드·입력)으로 다시 돌린 별도 run이다(경보율은 v1과 같았다). 아래 수치는 v2 기준.
| 입력, k, 모델 | 뺀 유형 | 시험 행 | 경보 건수(시드당) | 경보율 | 정상 오탐 건수(시드당, 분모 33,486) |
|---|---|---|---|---|---|
| 원본, 10, RF | HTTPS / XML / Probing | 5,484 / 3,925 / 9,747 | **0 / 1 / 0** | 0 / 0.000255 / 0 | 0 / 0 / 0 |
| 원본, 10, LightGBM | HTTPS / XML / Probing | 같음 | 0 / 0 / **128** | 0 / 0 / 0.0131 | 3 / 2 / 6 |
| 마스킹, 10, RF | 세 유형 | 같음 | 0 / 0 / 0 (세 시드 모두) | 0 | 0 / 1 / 0 (시드 최대) |
| 마스킹, 10, LightGBM | 세 유형 | 같음 | 0 / 0 / 0 | 0 | 1 / 8 / 5 (시드 최대) |
| 원본, 5, RF | HTTPS / XML / Probing | 같음 | 0 / 3,484 / 9,747 (시드 최대) | 0 / 0.888 / 1.000 | 0 / 3 / 0 (시드 최대) |
| 마스킹, 5, RF | HTTPS / XML / Probing | 같음 | 498 / 3,578 / 6,764 (시드 최대) | 0.091 / 0.912 / 0.684 | 118 / 239 / 226 (시드 최대) |
- **원본 k=10 RF에서 학습에 없던 유형의 경보는 사실상 없지만 0은 아니다**: XML이 시드당 1건(3,925행 중, 0.00025)이고 HTTPS·Probing은 0건이다. LightGBM은 Probing에서 시드당 128건(9,747행 중 0.0131)이 경보됐다. 마스킹 k=10은 RF·LightGBM 모두 세 유형에서 경보 0건이다. "경보율 0"은 반올림값이고, 정상 오탐도 표에 건수로 적었다(반올림 0.000은 RF 원본 k=10에서만 실제 0건).
- k=5에서는 XML과 Probing 경보율이 높다(RF 0.888·1.000, LightGBM 0.996·1.000). 이 값이 미학습 공격을 일반화해서 잡은 것인지 뺀 유형의 앞 5칸이 다른 공격 유형의 패턴과 닮은 것인지는 분해하지 않았다. 마스킹 k=5는 정상 오탐도 118~239건(시드당)으로 늘었다.
- 4분류 재현율이 아니라 경보율이며, 시험 결과로 정한 것이 아니다.

## 한계
- 캡처 단위 잠정 라벨(Probing은 CSV 확인 불가), 정상 출처 = 캡처, 공격자·피해자·도구가 유형마다 하나씩이라 교락이 완전하다. PoC로만 읽는다.
- Probing은 짝 캡처가 없어 캡처 안 시간 블록 분할이고 같은 도구·같은 서버의 반복 요청이다.
- 시드 3개, 같은 캡처·연결 묶음 상관. 대표 일반화 수치로 쓰지 않는다.
