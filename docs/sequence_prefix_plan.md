# A 초기 페이로드 패킷 수 비교 — 실행 계획

2026-10-31 서은빈 확정: LSTM은 이번 필수 범위에서 제외, 1D-CNN은 B 첫 결과 이후 조건부, A는 앞 5·10·20개 패킷 평가 다음에 미확인 문턱 평가를 진행한다. **이번 PR은 결정 기록과 실행 계획만 포함한다. 코드 작성·학습은 은빈님의 계획 확인 후 시작하고 PR 병합도 별도 승인받는다.**

## 질문과 비교 조건

질문은 “관측한 페이로드 패킷 수에 따라 알려진 13종의 오프라인 분류 성능이 어떻게 달라지는가”다. 실제 경과 시간·온라인 탐지 지연을 입증하는 실험은 아니다.

| 항목 | 고정 조건 |
|---|---|
| 입력 | 10/29 원본 재전처리본, 같은 행 ID·known 13종·held-out 5종·excluded/invalid 정책 |
| k | 신규 5·10·20, 비교 기준 30 |
| 분할 | 저장된 무작위·원본 30개 시퀀스 패턴 그룹 배정, 시드 0·1·2 |
| 모델 | 기존 RF·LightGBM, 각 100 trees·class_weight=balanced·workers=2·기존 세부 파라미터 |
| 학습 | 각 k별로 새 모델을 fit. 외부 train 전체 사용, 검증 분리·튜닝 없음 |
| 실행 수 | 3개 k × 분할 2 × 모델 2 × 시드 3 = 신규 학습 36회 / 실행 환경 |
| k=30 | 같은 환경의 검증된 sequence 단독 12회 재사용. 재학습하지 않음 |

맥 36회는 예비 실행, Colab CPU 36회는 보고서용 최종 실행이다. 둘을 실행하면 신규 학습은 총 72회이며, “36회”는 환경 하나의 조건 수다. Colab 66회 전체를 다시 실행하는 계획이 아니다.

## 입력을 자르는 방법

- 시퀀스 컬럼 `0`~`29`의 **30차원 구조를 유지**한다. 앞 k개 값은 방향 부호와 순서를 보존하고 k 이후는 모두 0으로 만든다. k=30은 원본과 완전히 같아야 한다
- 앞 k개만 남기고 컬럼 자체를 줄이지 않는다. RF의 기본 max_features 등 입력 차원에 연동되는 조건이 바뀌는 것을 피하고, 기존 30차원 패딩 정책을 유지한다
- 원래 k개보다 짧은 흐름은 기존 뒤쪽 0 패딩을 유지한다. 입력에는 실제 관측된 `min(비영 칸 수, k)`개 값만 남는다. 전체 흐름 길이·원본 패턴 ID·통계·TLS 지문·라벨은 모델 입력에 추가하지 않는다
- 학습·시험·unknown 모두 같은 변환을 적용한다. 30개로 학습한 모델의 시험 입력만 자르는 방식이 아니다. 원본·저장 분할·기존 결과를 덮어쓰지 않는다

## 분할과 겹침 감사

모든 k에서 동일한 행 배정을 유지해야 k별 성능 차이를 짝지어 볼 수 있다. 분할을 다시 고르거나 점수가 낮은 시드를 교체하지 않는다.

원본 30개 패턴이 분리돼도 앞 k개 패턴은 학습·시험에서 겹칠 수 있다. k=5·10·20·30별로 모델과 무관하게 다음을 감사한다.

- 각 분할·시드의 train/test 고유 접두 패턴 수, 공유 패턴 수
- 시험 행 중 train에 같은 접두 패턴이 있는 행 수·비율(분모: 해당 시험 전체 행), 클래스별 같은 지표
- unknown의 train 접두 패턴 일치도는 별도 표에 기록한다. unknown 라벨·성능을 모델 선택에 사용하지 않는다
- 그룹 분할의 원본 30개 패턴 train/test 겹침은 0이어야 한다. k<30의 접두 패턴 겹침은 측정 결과로 보고하며 자동으로 행 삭제·재분할하지 않는다

접두 패턴으로 다시 그룹 분할하는 평가는 시험 집합이 바뀌는 별도 설계다. 필요성이 생기면 사람에게 근거와 대안을 보고하고 별도 승인받는다.

## 짧은 흐름과 B 비교 형식

train/test/unknown별, split·seed·k별로 `rows`, `reached_k_rows`, `short_rows`, `short_fraction`, `padding_policy`를 기록하고 클래스별 표도 남긴다. 비율 분모는 각 표의 해당 partition/class 전체 행이며, 패턴 수와 행 수를 구분한다. k≤20의 짧은 흐름 여부는 기존 30개 시퀀스의 비영 칸 수로 정확히 판단할 수 있다.

기본 성능표는 짧은 흐름을 포함한 같은 시험 전체 행을 사용한다. 이는 “k번째 도달 시 또는 짧은 흐름 종료 시 이용 가능한 입력”에 대한 오프라인 평가다. 짧은 흐름 종료를 알기 전 판정했다고 주장하지 않는다. 실제 종료·타임아웃 처리와 시간 측정은 B에서 정의한다.

B와 k 단위(양방향 페이로드 패킷), trailing-zero 패딩, 짧은 흐름 건수·비율의 컬럼/분모를 맞춘다. B 구현 전 공유되는 정의와 다르면 양측 사람이 확인하고 맞춘다. 데이터·라벨이 다르므로 A/B의 절대 점수 우열 대신 k에 따른 경향을 비교하며, 일치도는 탐색적 보강 근거로 설명한다.

## 부분집합별 성능 보완 (10/31 검토 반영)

기본 성능표는 같은 시험 전체 행을 유지하고, 같은 모델의 저장 예측을 다음 부분집합으로 나눠 추가 표를 만든다. 필터마다 다시 학습하거나 분할을 바꾸지 않는다.

| 보고 집합 | 선택 규칙 | 용도 |
|---|---|---|
| all | known 시험 전체 행 | 기존 주 비교와 같은 분모 |
| reached_k | 원본 30개 시퀀스 비영 칸 수 ≥ k | k번째 패킷까지 도달한 흐름의 성능 |
| short | 원본 30개 시퀀스 비영 칸 수 < k | k 전에 끝나는 짧은 흐름의 성능 |
| prefix_seen | 앞 k개 입력 패턴이 해당 train에 존재 | 학습에서 본 접두 패턴에 대한 성능 |
| prefix_unseen | 앞 k개 입력 패턴이 해당 train에 없음 | 학습에서 못 본 접두 패턴에 대한 성능 |

각 split·seed·model·k·subset에 대해 rows, 전체 시험 대비 fraction, macro-F1·accuracy, 13종별 support·recall/F1·혼동 행렬을 남긴다. 패턴 일치 사전은 train으로만 만들며, 시험 라벨은 선택 규칙에 사용하지 않는다. `reached_k/short`와 `prefix_seen/prefix_unseen`은 각각 전체 시험을 정확히 양분하지만 서로 다른 축이므로 네 부분집합의 행 수를 함께 합산하지 않는다.

기존 공통 평가기는 고정 클래스 전체가 실제 라벨에 있어야 한다는 계약이 있으므로 그대로 유지한다. 클래스 누락·빈 집합을 처리하는 부분집합 평가는 같은 혼동 행렬/F1 정의를 쓰는 트랙 A 보조 로직으로 분리하고 테스트하며, 이를 위해 `src/common/`의 검사를 완화하지 않는다.

부분집합에 없는 클래스가 생길 수 있어 클래스 구성과 분모를 항상 함께 제시한다. macro-F1은 기존 known 13종 순서를 고정하고 공통 평가기와 같은 zero_division=0 정책을 쓴다. 실제 support=0인 클래스의 recall은 보고 표에서 NA로 구분한다. 빈 부분집합은 rows=0·지표=NA로 기록해 0점이나 누락된 성공 결과로 바꾸지 않는다. 세 시드 중 비어 있거나 클래스 구성이 달라지면 부분집합 집계에 유효 시드 수·support를 표시하고 전체 시험과 직접 같은 조건의 우열로 해석하지 않는다.

k마다 reached_k 집합이 달라지므로 그 곡선은 동일 흐름 집합의 짝 비교가 아니다. 주 paired 비교 36쌍은 기존처럼 전체 시험의 k=30 대비 차이로 유지한다. 부분집합별 결과는 구성 차이를 드러내는 보조 분석이며, prefix_unseen만 보고 일반화가 보장된다고 주장하지 않는다.

k=30에도 같은 보고 규칙을 적용한다. 기존 sequence 점수는 “최대 30개 페이로드 패킷” 입력의 점수로, 짧은 흐름에서는 흐름 전체 길이 시퀀스를 포함한다. 따라서 k=30을 모든 흐름의 종료 전 조기 성능으로 설명하지 않는다. Claude의 원본 시드 0 점검에서는 그룹 k=20의 short가 약 68%, 그룹 k=5의 prefix_seen이 약 78.7%였지만 이는 검토자의 사전 점검치다. 로컬·Colab 집계 파일로 다시 확인하기 전 최종 실험 결과로 사용하지 않는다.

추가 표는 신규 36회 및 기존 k=30의 행별 예측으로 계산한다. k=30은 해당 환경의 DATA_DIR/공유 Drive에 보존된 sequence 12개 실행의 예측을 읽고, 원본 행 ID·라벨·시험 배정·완전성 및 전체 점수가 기존 집계와 일치하는지 확인한다. 경로는 DATA_DIR에서 파생하고 행별 자료는 Git에 넣지 않는다. 필요한 기준선 예측이 없거나 검증에 실패하면 재학습을 자동 추가하지 않고 중단·보고한다. 이 보완으로 신규 학습 36회/환경의 범위는 늘어나지 않는다.

## 기준선과 구현 범위

재사용 기준선:

- 맥: `feature_group_2026-10-29_mac`의 sequence 12회
- Colab: `feature_group_2026-10-29_200024_colab`의 sequence 12회

집계·manifest·run_metadata.json을 읽어 완료·입력 SHA·원래 학습 코드 SHA·machine·버전·모델 설정·분할/시드·검증 미분리 정책을 확인한다. 환경이 다른 기준선을 혼합하지 않는다. 기준선 검사가 실패하면 중단해 보고하며, 자동으로 조건을 바꾸거나 추가 재학습하지 않는다.

구현은 새 `src/track_a/sequence_prefix_experiment.py`와 관련 테스트를 중심으로 한다. 입력 검증, 기준선 로더, 공통 모델·평가·저장·세 시드 집계 API를 재사용한다. `src/common/`과 기존 학습 코드는 수정하지 않는 것을 기본 범위로 한다. 공통 API 변경이 필요하면 사유를 보고하고 양측 확인을 받는다.

실행 식별 예시: `sequence_prefix_<날짜시각>_<환경>`(기존 ID 재사용 금지). `experiment=sequence_prefix`, `feature_group=sequence_prefix_k5/k10/k20`처럼 k를 집계 키에 포함하고, 별도 `k`·관측 차원 메타데이터를 보존한다. `n_features=30`과 k는 다른 값이다. 모델·분할·변환·기준선 소스·코드·패키지 버전·Git 기록을 남긴다.

## 결과와 보존

- metrics: 신규 36행, 모델별 macro-F1·정확도·학습 시간·행 수
- confusion: 36 × 13 × 13 = 6,084칸, 클래스 순서·시험 분모 고정
- summary: 신규 12조건의 세 시드 평균·표본 표준편차(ddof=1). 시드 간 시험 집합 겹침이 있어 독립 신뢰구간으로 해석하지 않는다
- k=30 비교표: 원본 기준선 12행을 출처와 함께 참조해 총 48행·16조건의 곡선 작성. 기존 결과의 실행 ID·experiment·메타데이터는 변경하지 않는다
- paired: 같은 split·model·seed의 k별 k=30 대비 점수 차이 36쌍
- class_scores: 클래스별 recall/F1과 정상 오분류율을 분모와 함께 기록
- subset_scores·subset_class_scores·subset_confusion: 전체/도달/짧음/접두 일치/불일치별 성능과 support. 6,084칸은 신규 36회 전체 시험의 혼동 행렬 수이며, 부분집합·k=30의 추가 표는 별도 집계한다
- prefix_overlap·short_flows: 위 감사 결과. 학습 전 사전 검사와 학습 후 보고에 동일 자료 사용
- manifest·run_metadata.json: 36개 실행의 입력·설정·provenance 보존. 완료 검증 후에만 완료 표시

Git에는 배치 집계·혼동 행렬·감사·메타데이터를 남긴다. 개별 중복 폴더는 아카이브 검증 뒤 추적 제외하며, 행별 예측·배정은 `DATA_DIR/predictions/<run-id>/`에만 저장한다. 새 실행이 중단되면 완료 조건만 기록하고 불완전 상태를 유지한다. 미완료 파일을 최종 집계나 성공 결과로 쓰지 않는다.
