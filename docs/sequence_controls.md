# 시퀀스 순서 섞기와 학습 패턴 조회 기준선

원본 재전처리 데이터와 [특징군 비교](feature_group_experiment.md)의 외부 분할 6개를 그대로 사용한다. 이 단계는 RF·LightGBM의 위치 정보 대조와 13종 해시 조회 기준선이다. CNN·LSTM, 미확인 거절 문턱, 최종 Colab 수치는 포함하지 않는다.

## 순서 섞기

- 원본 92,034행에서 0은 모두 뒤쪽에만 있으며 전부 0인 행은 없음을 확인했다. 패딩 위치·유효 패킷 수는 유지하고 각 행의 **0이 아닌 부호 있는 길이 값만 독립적으로 순열화**한다. 길이 값의 집합·부호·0 위치는 그대로다
- 각 행의 원본 source_row와 섞기 시드로 난수 생성기를 만든다. 행 정렬이나 청크 크기가 달라도 같은 행·시드는 같은 결과다. 모든 행에 같은 열 순열을 적용하는 방식은 순서 파괴가 아니므로 쓰지 않는다
- 분할·그룹 ID는 **섞기 전 원본 패턴**을 유지한다. 섞은 패턴으로 재분할하지 않는다. 같은 시드의 섞인 입력을 두 모델·두 분할에 재사용한다
- 분할 2 × 모델 2 × 시드 3 = **12회 재학습**. 외부 train 전체, RF·LightGBM 100개 트리·balanced·worker 2개, 검증 분리·튜닝·스케일링 없음
- 원순서의 시퀀스 단독 12조건은 완료된 기존 48회 배치에서 가져온다. 같은 machine·입력 파일·코드·모델 파라미터·라이브러리 버전과 validation=0을 검사하고 조건별 점수 차이(섞기−원순서)를 기록한다
- 분할·모델·섞기 시드는 0/1/2로 함께 바뀐다. 분할·학습·섞기 변동을 분리하지 않으며, 한 분할에 대한 섞기 반복 신뢰구간이 아니다

이 대조는 트리 모델의 패킷 위치 정보 의존도를 본다. 섞기는 행간 동일 패턴의 반복 관계도 바꾸며, 패킷 수·길이 분포·방향 수는 보존한다. 점수 차이를 순수한 시간 순서의 인과 효과로 해석하거나 CNN/LSTM 필요성을 확정하지 않는다. 추후 순서 모델 비교가 필요하다.

## 해시 룰

- 원본 30개 시퀀스의 검증된 SHA-256 ID를 키로 사용한다. **train 행의 라벨만** 세어 패턴별 최빈 클래스를 저장한다. 충돌 라벨의 표 수가 같으면 문자열순으로 선택한다
- 시험에서 본 적 있는 패턴은 저장 라벨을 조회하고, 처음 보는 패턴은 **train 전체 최빈 클래스**로 예측한다(동률은 문자열순). 처음 보는 패턴을 임의로 악성·미확인이라고 판정하지 않는다
- 알려진 13종 전체 시험 행에 대해 macro-F1·정확도·13×13 혼동 행렬을 계산한다. 조회 성공 행만 골라 전체 성능으로 보고하지 않는다. 조회율·성공 행 정확도·클래스별 조회율을 별도로 저장한다. 조회 성공 0행이면 성공 행 정확도는 비워 둔다
- 분할 2 × 시드 3 = **6회**. 랜덤 모델은 없으며 시드는 외부 분할만 바꾼다. 그룹 분할에서는 학습·시험 원본 패턴이 겹치지 않아 조회율 0이 예상되며, 전체 점수는 최빈 클래스 fallback의 성능이다
- unknown 예측도 DATA_DIR에 저장하지만 known 지표에서 제외한다. 이 조회 규칙은 미확인 탐지기가 아니다. 전체 데이터의 패턴-라벨 사전을 미리 만드는 oracle을 사용하지 않는다

## 실행·산출물

```sh
# DATA_DIR과 MACHINE을 먼저 설정한다.
python -m src.track_a.sequence_controls \
  --run-id sequence_controls_2026-10-29_mac \
  --baseline-run-id feature_group_2026-10-29_mac --workers 2
```

Colab은 workflow의 CPU 런타임·고정 버전 확인 후, 같은 환경에서 완료한 원순서 48회 배치의 ID를 baseline-run-id로 전달한다. 새 run-id를 사용하며 맥 기준선과 Colab 결과를 직접 짝지어 비교하지 않는다.

Git의 batch 디렉터리에는 18회 metrics.csv·confusion.csv(3,042칸), 6조건 summary.csv, 12조건 paired.csv, 해시 클래스별 조회율 78행 hash_coverage.csv, manifest.json을 남긴다. 개별 디렉터리는 공통 API의 metrics·confusion·metadata를 보존한다. 행별 예측·최종 배정은 DATA_DIR/predictions 아래에만 둔다. 해시 예측의 lookup_hit은 조회 여부이며 확률이 아니므로 max_probability를 만들지 않는다.

입력·기준선·실행 코드의 SHA-256, 시작 Git 커밋·dirty, 각 모델의 설정·버전을 기록한다. 기존 run-id는 덮어쓰지 않고 실패 시 complete=false로 남긴다. 18조건과 12개 짝 비교가 완료되고 입력·코드가 불변일 때만 complete=true다. 맥 수치는 예비이며 Colab 최종 수치는 별도 실행한다.

## 검사

`python -m unittest discover -s tests`: 34개 통과. 새 검사에는 값·부호·패딩 보존, 행 ID별 재현, 내부 0/결측 거부, train 라벨만 조회, 시험·unknown 라벨 변경 시 예측 불변, 그룹 미조회 전체 점수와 fallback, 다른 machine/불완전 원순서 기준선 거부가 포함된다.
