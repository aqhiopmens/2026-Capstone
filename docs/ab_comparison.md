# A/B 경향 비교 (초안)

토론 안건 3(11/4) 합의에 따라 **경향을 미리 정하지 않고** 트랙 A(Malicious_TLS)와 트랙 B(HIKARI)의 결과를 같은 항목에 나란히 놓는다. 데이터·클래스·관측 예산·환경이 달라 **절대 F1의 우열 비교는 하지 않는다.** 방향이 실제로 일치한 항목만 "부합"으로 쓰고, 그 밖의 것은 "직접 비교 불가"로 둔다. A·B 모두 단일 데이터셋의 관찰이며 일반화 증거가 아니다.

## 0. 비교 대상

| 항목 | 트랙 A | 트랙 B |
|---|---|---|
| 데이터 | Malicious_TLS 92,034행, 알려진 13종(+보류 5종) | HIKARI 443 플로우, 정상 대 공격 2종. XML(04-12·04-17), HTTPS(04-11·04-16) |
| 평가 틀 | 무작위 분할 대 원본 패턴 그룹 분할, 시드 3 | 날짜 시간 분할 양방향, 시드 3 |
| 입력 | 전체·지문·통계·시퀀스, 앞 k개 시퀀스 | 앞 k개 시퀀스(seq)와 요약(counts) |
| 최종 환경 | Colab CPU 2026.07(은빈) | XML·HTTPS 평가 Windows, HTTPS 평가는 Colab 최종 실행(강민) |
| 라벨 | 데이터 제공 라벨 | 캡처 단위 규칙 라벨(XML, HTTPS). HTTPS는 CSV와 상충해 **잠정 라벨** |

## 1. 분할이 엄격해질 때

| 지표(3시드 평균) | 무작위 | 그룹 | 변화 |
|---|---|---|---|
| A 시퀀스만 RF | 0.9142 | 0.8798 | −0.0344 |
| A 시퀀스만 LightGBM | 0.9176 | 0.8828 | −0.0348 |
| A 전체 특징 RF | 0.9721 | 0.9621 | −0.0100 |
| A 전체 특징 LightGBM | 0.9783 | 0.9761 | −0.0022 |

B에는 무작위 분할 기준선이 없다(시간 분할만 평가). 가장 가까운 대조는 **같은 피해자만(only_242104) 대 처음 보는 피해자 포함(all)** 이다.

| B HTTPS RF seq macro-F1 | k=5 | k=10 | k=20 | k=30 |
|---|---|---|---|---|
| 04-11→04-16, .242.104만 | .999 | .999 | .999 | .999 |
| 04-11→04-16, 새 피해자 포함 | .685 | .685 | .684 | .685 |
| 04-16→04-11, .88.81을 학습에서 제외 | .820 | .821 | .833 | .912 |
| 04-16→04-11, .88.81을 학습에 포함 | .939 | .997 | .996 | .997 |

**읽는 법**: A는 엄격할수록 소폭 낮아진다(−0.002~−0.035). B는 조건에 따라 하락 폭이 0에서 −0.31까지 크게 다르다. "엄격한 조건에서 낮아진다"는 **방향은 부합**하지만, A의 그룹 분할과 B의 날짜·피해자 변화는 서로 다른 검증이고 크기는 비교하지 않는다. 같은 현상의 재현으로 묶지 않는다.

## 2. 앞 k개 패킷만 쓸 때

| 모델·분할 | k=5 | k=10 | k=20 | k=30(전체 시퀀스) |
|---|---|---|---|---|
| A RF 무작위 | 0.9095 | 0.9151 | 0.9148 | 0.9142 |
| A RF 그룹 | 0.8823 | 0.8554 | 0.8556 | 0.8798 |
| A LightGBM 그룹 | 0.8917 | 0.8932 | 0.8853 | 0.8828 |
| B XML RF seq (04-12→04-17) | 0.9999 | 1.0000 | 해당 없음 | 해당 없음 |
| B HTTPS LightGBM seq, 04-16→04-11 .242.104만 | .820 | .821 | .820 | .820 |

**읽는 법**: 두 트랙 모두 k가 커진다고 점수가 단조롭게 오르지 않는다(A 그룹 RF는 비단조, B XML은 k=5부터 포화). B HTTPS의 RF는 해당 조건에서 k가 클수록 오르지만(.820→.912) LightGBM은 오르지 않아 모델별로 다르다. 방향이 **일치한다고 쓰지 않는다**. B XML은 공격 플로우가 모두 12개 이하라 k=20·30을 평가하지 못했다.

## 3. 입력 정보를 가리는 통제

| 통제(원본 대비 macro-F1 변화) | A (Colab, 무작위 / 그룹) | B XML (시간 분할 평균) |
|---|---|---|
| 앞 k개 순서 섞기 RF | −0.126 / −0.093 | −0.0021 |
| 앞 k개 순서 섞기 LightGBM | −0.048 / −0.080 | −0.0007 |
| 첫 패킷 길이 가리기 | A에서 하지 않음 | −0.0015 |
| 부호(방향) 제거 | A에서 하지 않음 | 0.0000 |
| 크기를 로그 구간으로 묶기·방향만 | 하지 않음 | B HTTPS 짝 비교 [결과](track_b_https_robust.md) |

**읽는 법**: 순서 섞기는 두 트랙 모두 점수를 내리는 쪽이지만 **크기가 크게 다르다**(A −0.05~−0.13, B XML 약 −0.001). A의 모델은 순서 정보를 실제로 쓰는 반면 B XML은 순서를 지워도 점수가 거의 유지되는, 쉽게 분리되는 데이터였다. 첫 패킷 마스킹은 A에서 하지 않았으므로 공통 통제로 쓰지 않는다. 하나의 방향("둘 다 하락")으로 요약하면 효과 크기 차이를 숨긴다.

## 4. 환경 간 재현

| 항목 | A (맥 대 Colab) | B (Windows 대 Colab) |
|---|---|---|
| 점수 | 특징군 비교 RF 최대 차이 0.0018, 섞기 RF 0.0058, LightGBM·해시 일치 | HTTPS 192회 macro-F1·정확도 차이 최대 0.0 |
| 확률·문턱 | 미확인 문턱 unknown 거절률 최대 24.3%p, 시드 1의 문턱 이동으로 known 거절 7.0%→15.4% | 해당 없음(저장 예측 3,433,200행 불일치 0, `max_probability` 3행만 1.1e-16) |

**읽는 법**: 점수 수준의 환경 차이는 A에서 작고 B에서 없다. 단 A의 미확인 거절 문턱은 환경이 바뀌면 크게 흔들렸고 B는 문턱 실험을 하지 않았으므로 비교할 수 없다.

## 5. 요약: 방향이 부합하는 것과 아닌 것

| 항목 | 판단 |
|---|---|
| 엄격한 조건에서 낮아진다 | 방향 부합(크기·검증 종류가 다름). B는 직접 대조 기준선 없음 |
| 처음 보는 조건에 약하다 | 주제는 유사(A 미확인 위협 거절 불안정, B 새 피해자 recall 0)하나 지표가 달라 같은 현상으로 묶지 않음 |
| k가 커지면 단조 개선 | 두 트랙 모두 보장 안 됨 |
| 순서 섞기로 하락 | 방향 부합, 효과 크기 매우 다름 |
| 환경 차이 | A 소폭 점수 차이·문턱 불안정, B 점수 차이 없음 |

## 한계

- A는 Malicious_TLS, B는 HIKARI 두 공격이다. 데이터·클래스·관측 예산·환경이 달라 위 항목은 경향 나열이며 한쪽이 다른 쪽을 재현한 것이 아니다.
- B HTTPS는 잠정 라벨, 날짜·피해자 교락이 있고, 입력 견고성 결과는 시험에서 약한 조건을 본 뒤 고른 탐색적 결과다.
- A·B 수치는 각각 저장소의 Colab 집계(A: `feature_group_…_colab`, `sequence_controls_…_colab`, `sequence_prefix_…_colab`, B: `track_b_early_…`, `track_b_control_…`, `track_b_https_eval_…_colab`)에서 가져왔다. 이 표는 이 수치를 옮겨 적은 것이라 최종 보고서에 쓸 때 원본 CSV와 다시 대조한다.
