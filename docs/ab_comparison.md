# A/B 경향 비교 (초안)

토론 안건 3(11/4) 합의에 따라 **경향을 미리 정하지 않고** 트랙 A(Malicious_TLS)와 트랙 B(HIKARI)의 결과를 같은 항목에 나란히 놓는다. 데이터·클래스·관측 예산·환경이 달라 **절대 F1의 우열 비교는 하지 않는다.** 두 트랙은 서로 다른 조작을 했기 때문에 대부분의 항목은 "직접 비교 불가"이며, 같은 방향임을 말할 수 있는 곳만 그 범위를 적는다. A·B 모두 단일 데이터셋의 관찰이며 일반화 증거가 아니다. 3시드 평균은 독립 데이터셋 3개가 아니라 같은 원본의 반복이다. 트랙 A는 `feature_group_experiment.py`에서 분할 시드와 모델 시드를 함께 바꾸므로 분할 변동과 모델 변동이 분리되지 않고, 트랙 B는 날짜 분할을 고정한 채 모델 시드만 바꾼다.

## 1. 분할 조건이 달라질 때 (직접 비교 불가)

트랙 A는 **분할 방식**을 바꿨고 트랙 B는 **시험 모집단 또는 학습 공격 표본**을 바꿨다. 같은 조작이 아니므로 방향을 하나로 묶지 않는다.

| A (3시드 평균 macro-F1) | 무작위 | 그룹 | 변화 |
|---|---|---|---|
| 시퀀스만 RF | 0.9142 | 0.8798 | −0.0344 |
| 시퀀스만 LightGBM | 0.9176 | 0.8828 | −0.0348 |
| 전체 특징 RF | 0.9721 | 0.9621 | −0.0100 |
| 전체 특징 LightGBM | 0.9783 | 0.9761 | −0.0022 |

위 표의 전체·시퀀스 4조건은 그룹 분할에서 낮아졌다. 다른 특징군에는 일반화하지 않는다(예: 지문만 RF는 0.8428→0.8545, LightGBM 0.8385→0.8535로 오히려 높아졌다).

| B HTTPS RF seq macro-F1 | k=5 | k=10 | k=20 | k=30 | 무엇이 달라졌나 |
|---|---|---|---|---|---|
| 04-11→04-16, .242.104만 | .999 | .999 | .999 | .999 | 시험에 .88.81 없음 |
| 04-11→04-16, all | .685 | .685 | .684 | .685 | 시험에 .88.81 공격 3,951행 추가(학습은 같음) |
| 04-16→04-11, .88.81 학습 제외 | .820 | .821 | .833 | .912 | 학습에서 .88.81 제외 |
| 04-16→04-11, .88.81 학습 포함 | .939 | .997 | .996 | .997 | 학습에 .88.81 공격 3,951행 추가 |

정방향의 하락은 **시험 모집단에 처음 보는 피해자를 넣어서**, 역방향의 상승은 **학습 공격 표본을 늘려서** 생긴 차이이고 서로 다른 조작이다. B에는 분할 엄격성 전후의 기준선이 없으므로 A의 무작위→그룹 하락과 "같은 방향이다"라고 쓰지 않는다.

## 2. 앞 k개 패킷만 쓸 때

| 모델·분할 | k=5 | k=10 | k=20 | k=30(최대 30칸) |
|---|---|---|---|---|
| A RF 무작위 | 0.9095 | 0.9151 | 0.9148 | 0.9142 |
| A RF 그룹 | 0.8823 | 0.8554 | 0.8556 | 0.8798 |
| A LightGBM 그룹 | 0.8917 | 0.8932 | 0.8853 | 0.8828 |
| B XML RF seq (04-12→04-17) | 0.9999 | 1.0000 | 평가 안 함 | 평가 안 함 |
| B HTTPS LightGBM seq, 04-16→04-11 only_242104 | .820 | .821 | .820 | .820 |

**읽는 법**: 두 트랙 모두 k가 커진다고 점수가 단조롭게 오르지 않는다(A 그룹 RF는 비단조, B XML은 k=5부터 포화). B HTTPS RF는 해당 조건에서 k가 클수록 오르지만(.820→.912) LightGBM은 오르지 않아 모델별로 다르다. 방향이 일치한다고 쓰지 않는다. B XML은 공격 플로우가 모두 12개 이하라 k=20·30을 평가하지 못했다.

## 3. 입력 정보를 가리는 통제

| 통제(원본 대비 macro-F1 평균 변화) | A (Colab, 무작위 / 그룹) | B XML (조건별 시드 평균의 범위) |
|---|---|---|
| 앞 k개 순서 섞기 RF | −0.126 / −0.093 | 평균 −0.0021 |
| 앞 k개 순서 섞기 LightGBM | −0.048 / −0.080 | 평균 −0.0007 |
| B XML 순서 섞기 전체 | | 조건별 −0.0034~+0.0014(개선 조건도 있음) |
| 첫 패킷 길이 가리기 | A에서 하지 않음 | 평균 −0.0015 |
| 부호(방향) 제거 | A에서 하지 않음 | 평균 0.0000 |

**읽는 법**: 순서 섞기의 **평균 변화량은 두 트랙 모두 음수**이지만 크기가 크게 다르다(A −0.05~−0.13, B XML 약 −0.001). B XML은 조건에 따라 개선되는 경우도 있어 "둘 다 내린다"로 요약하지 않는다. A는 최대 30칸, B는 k=5·10으로 관측 예산도 다르다. 첫 패킷 마스킹은 A에서 하지 않았으므로 공통 통제로 쓰지 않는다. 입력 견고성(로그 구간화·방향만)은 B HTTPS에서만 시도했다([결과](track_b_https_robust.md), 탐색적).

## 4. 환경 간 점수 차이

점수 차이의 **범위는 실험마다 다르다.** 하나의 숫자로 합치지 않는다.

| 항목 | A (맥 대 Colab) | B (Windows 대 Colab) |
|---|---|---|
| 특징군 비교 | RF 최대 0.0018, LightGBM 일치 | 해당 없음 |
| 순서 섞기 | RF 최대 0.0058, LightGBM·해시 일치 | 해당 없음 |
| 앞 k개 | RF 최대 0.0024, LightGBM 일치 | 해당 없음 |
| 미확인 문턱 실험의 닫힌 13종 | 별도 실행에서 최대 0.0097 | 해당 없음 |
| HTTPS 기본 192회 | 해당 없음 | macro-F1·정확도 차이 최대 0.0, 예측 3,433,200행 불일치 0, `max_probability` 3행만 1.1e-16 |

미확인 문턱(OOD) 실험의 두 수치는 서로 다른 조건이다. unknown 거절률 24.3%p는 48개 정책 중 개별 최대 한 건(group/all/RF/시드 1/5%)이고, 시드 1 문턱 이동에 따른 group/sequence/RF 주 5% known 거절 7.0%→15.4%는 별도 조건이다. 문턱 민감성 관찰이며 원인을 문턱 이동 하나로 확정하지 않는다.

## 5. 요약

| 항목 | 판단 |
|---|---|
| 분할 조건 변화 | **직접 비교 불가.** A는 분할 방식, B는 시험 모집단·학습 공격 표본을 바꿨다. A의 표시한 4조건은 그룹 분할에서 하락(지문은 상승) |
| 처음 보는 조건에 약하다 | 주제는 유사(A 미확인 위협 거절 불안정, B HTTPS 기본 RF seq의 04-11→04-16 all에서 .88.81 부분집합 recall 0(4개 k×3시드 12회); #37의 `dir` k=5는 recall 약 0.925지만 정상 specificity가 급락한 오탐 급증 반례라 B 전체로 일반화하지 않음)하나 지표가 달라 같은 현상으로 묶지 않음 |
| k가 커지면 점수가 오른다 | 두 트랙 모두 단조 개선이 보장되지 않음 |
| 순서 섞기 | 평균 변화는 두 트랙 모두 음수, 효과 크기 매우 다름, B XML은 개선 조건도 있음 |
| 환경 차이 | A는 실험별 소폭 점수 차이와 문턱 민감성, B HTTPS는 점수 차이 0 |

## 한계

- A는 Malicious_TLS, B는 HIKARI 두 공격이다. 데이터·클래스·관측 예산·환경이 달라 위 항목은 경향 나열이며 한쪽이 다른 쪽을 재현한 것이 아니다.
- B HTTPS는 잠정 라벨, 날짜·피해자 교락이 있고, 입력 견고성 결과는 시험에서 약한 조건을 본 뒤 고른 탐색적 결과다.
- 수치는 위 출처의 집계 CSV에서 옮겨 적었다. Codex가 A 쪽(특징군·순서 섞기·앞 k개 Colab 집계)과 B XML 표·통제 평균을 원본 CSV와 대조해 반올림 범위에서 일치를 확인했다. 최종 보고서에 쓸 때 다시 대조한다.
